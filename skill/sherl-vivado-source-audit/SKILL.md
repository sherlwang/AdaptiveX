# Vivado 来源与依赖核验

用于回答三个独立问题：受保护参考有没有变化、交付文件来自哪里、工程有没有遗留外部路径。先划清参考树、可修改工程和报告目录，再读取或运行脚本。用户没有要求迁移时，不据此改源文件、升级 IP 或重建工程。

脚本只读源输入，只向指定的新报告文件写入；报告放在被核验树之外，包括额外指定的共享源码根和搜索目录。需要 Python 3.9 及以上，仅用标准库。输出存在时停止，不覆盖旧证据。退出码 `0` 为该项静态检查满足，`1` 为发现变化或待审项。可定位的单文件读取、编码或解析失败写入完整报告并继续，不能隐去这部分检查范围；入口不可读或无法解析、输出被拒绝等使任务不能开始或完成时返回 `2`。

## 1. 保护冻结参考

操作前建立快照，操作后对同一份快照核验：

```bash
python3 <skill>/scripts/tree_snapshot.py snapshot <reference-tree> --output <reports>/before.json
python3 <skill>/scripts/tree_snapshot.py verify <reference-tree> --snapshot <reports>/before.json --output <reports>/after.json
```

比较每个文件的 SHA-256、长度、相对路径、权限及纳秒修改时间，包括目录和链接目标。新增、删除、内容或元数据变化均单独列出。符号链接只记录、不遍历；特殊文件使结果不完整。运行期间应让输入树静止，脚本检测到读取时变化则报错。

复制后的树只需比较内容时可以显式加 `--content-only`，元数据差异仍保留在报告中。保护原始参考时不要擅自使用该选项。快照不涵盖所有权、ACL、扩展属性和访问时间，不能声称这些也保持不变。

## 2. 审计新工程的路径依赖

```bash
python3 <skill>/scripts/audit_sources.py project <project.xpr> --output <reports>/paths.json
```

检查 XPR 注册文件、常见 Vivado 项目宏、源树中的 XCI 输出/初始化文件路径、BD 的 `xci_path` 与生成目录，以及 Verilog 的字面量 `include`、`$readmemh/$readmemb`。所有待审项及候选文件都写进报告，没有自动截断数量。

- 默认要求依赖位于 XPR 所在工程内。确有用户授权的共享库，显式追加 `--allow-root <shared-tree>`，并在交付结论中说明该外部依赖，不能继续称为完全自包含。
- 已知编译或运行搜索目录可追加 `--search-dir <directory>`；这个参数只用于静态搜索，不修改 Vivado 配置。未知宏、动态文件名、非空 IncludeDirs/IPRepoPaths 不执行 Tcl 推测，列为待审。
- 同名文件不等于确定依赖。报告分开列出明确路径匹配与仅同名候选；多个匹配要核对，不能随意挑一个。
- 任意路径组件出现符号链接均列为待审，不通过该链接读取源文件。路径所在真实位置仍与允许根核对；父目录链接和直接文件链接采用相同口径。
- `$readmem*` 的实际查找与仿真工作目录、内存文件暂存有关。即使找到唯一文件，也不能据此宣称运行时一定装载正确。
- 缺失的 BD 子 IP 输出可能可再生成，但必须明确记录，由后续 Vivado 检查确认，不能当作无关文件静默忽略。

HDL、XCI、BD文本分析使用严格UTF-8。非UTF-8字节按文件记录为`unsupported_encoding`，保留原字节，不猜编码、不忽略错误、不自动转码；该文件的文本检查尚未完成。普通文件的字节比较不受文本编码影响。

脚本不会解析 VHDL、预处理条件、加密 HDL 或递归 Tcl；不会证明模块连接、ROM 顺序或 IP 许可证可用。`STATIC_CLEAR` 只表示本脚本支持的静态检查没有待审项。需要保证工程能打开或生成 IP 时，另行执行用户授权的 Vivado 检查，并把结果与静态结论分开。

## 3. 核对来源和必要路径变化

两棵树按相同相对路径对应时：

```bash
python3 <skill>/scripts/audit_sources.py compare <reference-tree> <candidate-tree> --output <reports>/source-diff.json
```

普通文件按字节比较，链接按目标文本比较，增删文件单独列出。脚本采用一个窄的工程复制比较口径：

- XCI 只允许既有 `RUNTIME_PARAM.OUTPUTDIR` 的值变化，其他 XML 字段均比较；格式空白及 XML 属性次序不作为功能差异。
- BD 只允许既有 `/design/design_info/gen_directory` 的值变化，其他 JSON 内容均比较。
- 以上两项只描述可接受的路径元数据类别，仍须核对新路径确实指向新工程；它们不授权修改任何硬件参数。
- Vivado 可能在保存时展开 PS 默认参数。脚本将这些展开列为未审差异：不能直接称为硬件功能改变，也不能因为“像默认值”而整批忽略。需要结合原配置和工具结果确认，或在工具关闭后按已授权的输入来源恢复。
- 重新排布目录、允许的顶层接口编辑等不由脚本猜测映射。先明确来源映射和允许改动，分别比较对应子树；记录例外及逐项差异。

最终说明区分字节一致、仅路径元数据差异、人工核实的必要接口改动和仍未确认内容。不用“静态清晰”代替端到端正确性，也不把生成 bit 当作板测通过。
